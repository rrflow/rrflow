## Implementation and traceability

`tests/support/sustained.rs::PointRun` owns `ManagementTask<BackupEvidence>`.
At measured sequence 14, a start observation is checkpointed before launch.
Nonfinal segments poll completion without joining; the last measured segment
settles the same task while continuing resource samples. A second poll after
the offered interval catches completion during that interval. Session rotation
cannot close a session still used by the task. No offered time origin changes.

`tests/support/sustained/management.rs` holds one JoinSet entry, rejects a
second task and an already-expired launch, applies `timeout_at` to the original
deadline and checks completion time. Nonblocking collection preserves errors;
dropping the owner aborts its task. `lifecycle::backup_started` binds launch
time while preserving the actual create-backup and verifying-list operations.
The installed smoke retains a verified receipt behind a bounded handoff while
real foreground write/read work completes, then releases and joins it before
restart and replay. The handoff is explicitly test coordination, not simulated
archive verification or a throughput measurement.

`SustainedSegment.backup_started_ns` is an optional additive evidence field.
The existing same-segment receipt remains self-contained. A later receipt
requires its earlier start in the checked segment chain. `BackupTracker` keeps
only fixed-count point/seed scalar state and a rolling start digest, never old
ledgers or payloads. It observes attempts only after independent ledger binding.
Among acknowledged mixed writes ending after backup start, the smallest start
proves overlap iff it precedes archive completion. Missing starts, duplicates,
wrong owners/phases, expired work, nonoverlap and unfinished completion fail.
Publication validates on a copy; rejected evidence cannot advance tracker state.
The offline verifier reconstructs this state while reading the same chain.

`ProgressEvent::BackupStarted` preserves an in-flight operation even if a later
segment cannot publish. Progress and accepted start markers must reconcile;
an unbound marker cannot support a completed campaign. Existing reader/cold
and final readback checks remain. Only the segment and progress-event schemas
change, generated by the existing Rust schema/golden machinery.

Changed: CLI sustained driver/lifecycle, evaluation sustained/progress/module
wiring, two generated schemas, this record, owning evidence links and generated
navigation/inventory. Created: management helper/tests, bounded backup tracker
and its contract histories. The old segment-local backup JoinSet/join loop is
replaced directly; no parallel driver, runtime service or fallback is added.
